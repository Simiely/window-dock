# Windows 窗口 Dock：只读探针实测结果与实施计划

> 本文分三部分：**只读实测数据**（本轮真机跑出）、**探针工程与运行说明**、**基于实测的实施计划**。
> 所有数字都来自 `ProbeHost.exe --readonly` 的输出（`probe\out\readonly-console.txt`、`readonly.json`），未做任何窗口创建/移动/激活、未注册热键、未发送输入。
> 需要交互才能得到的结论一律标注「**需实测**」，不填推测数字。

---

## 0. 一句话结论

只读部分已经确认了三件会影响架构的事：

1. **枚举必须重过滤**：本机 `EnumWindows` 返回 483 个顶层窗口，按 Alt+Tab 规则过滤后只剩 **17 个**。直接枚举会把 466 个隐藏/工具/挂起窗口当成候选。
2. **命中判定必须用 `DWMWA_EXTENDED_FRAME_BOUNDS`，且公差按 ±8 px 设计**：`GetWindowRect` 比视觉边界最多外扩 8 px（实测 L/T/R/B 各方向最大 8），且**不同窗口风格差值不同**（Chromium 有 3/8 个窗口差值为 0），不存在一个固定补偿值。
3. **最小化窗口不能用 `GetWindowRect` 做快照**：实测 5 个最小化窗口里有 4 个的矩形是 `-32000,-32000,...` 哨兵值，真实位置只在 `WINDOWPLACEMENT.rcNormalPosition` 里。

另外两项条件本机不满足，只能标注条件：**混合 DPI**（两块屏都是 96 DPI / 100%）、**UWP 识别**（当前没有 `ApplicationFrameWindow` 窗口）。

## 1. 本机环境（实测）

| 项 | 实测值 |
|---|---|
| 系统 | `10.0.26100.0`，build **26100**，x64 进程 |
| 显示器 | 2 块，`\\.\DISPLAY1` = `0,0,2560,1440`（工作区 `0,0,2560,1400`）；`\\.\DISPLAY2` = `-2560,0,0,1440`（工作区 `-2560,0,0,1400`） |
| 缩放 | **两块屏都是 96 DPI = 100%**（`GetDpiForMonitor` 与真实窗口 `GetDpiForWindow` 交叉验证一致） |
| 虚拟屏幕 | 物理像素范围 X `[-2560, 2560)`，Y `[0, 1440)` |
| 进程权限 | `selfElevated=False`（非管理员） |
| UAC | `EnableLUA=1`、`ConsentPromptBehaviorAdmin=5`、`PromptOnSecureDesktop=1` → **UIPI 生效** |
| 提权窗口 | 当前桌面有 **3** 个提权进程的可见窗口（只读检测） |
| PowerToys | 进程：`PowerToys`、`PowerToys.QuickAccess`、`PowerToys.Awake`、`PowerToys.FancyZones` |

坐标换算（实测 `dpi=96` 时 `PhysicalToLogicalPointForPerMonitorDPI` 返回与输入完全相同）：

```
physical = round(dip * dpi / 96)
dip      = round(physical * 96 / dpi)
本机 96 DPI → 1 DIP = 1 px，两屏只差一个 X 平移量 -2560
```

## 2. 只读实测数据表

### 2.1 窗口枚举与过滤

| 探针 | 实测数据 | 通过与否 | 结论 |
|---|---|---|---|
| 顶层窗口枚举 | `total=483` | — | `EnumWindows` 的数量完全不能当候选数 |
| Alt+Tab 规则过滤后 | **`usable=17`** | **PASS（规则可用）** | 过滤比例 3.5%，过滤是必需项，不是优化项 |
| 隐藏窗口 `IsWindowVisible=false` | `433` | — | 绝大多数是 shell/消息窗口 |
| 无标题 | `19` | — | 必须在过滤链里 |
| `WS_EX_TOOLWINDOW` | `28` | — | 必须在过滤链里 |
| cloaked（`DWMWA_CLOAKED≠0`） | `26`（`0x1` = 15，`0x2` = 11） | — | 即使 `IsWindowVisible` 为真也可能被 cloaked，必须单独判 |
| 零尺寸 | `6` | — | `Right-Left<=0` 要剔除 |
| 带 owner 的窗口 | `183` | — | 绝大多数是对话框/弹出窗，不能只靠 owner 判据 |
| 自身进程窗口 | `0`（readonly 不建窗口） | — | 交互模式下必须排除自身 |

**结论**：过滤链固定为
`IsWindowVisible && !IsCloaked && !WS_EX_TOOLWINDOW && pid != self && title.Length>0 && width>0 && height>0`。
本机基线：**枚举 483 / 可用 17**。

### 2.2 `GetWindowRect` vs `DWMWA_EXTENDED_FRAME_BOUNDS`

差值定义为 `GetWindowRect - EXTENDED_FRAME_BOUNDS`，正值表示窗口矩形比视觉边界更靠外。

| 窗口风格（实测分类） | n | L | T | R | B | 完全为 0 的窗口数 |
|---|---|---|---|---|---|---|
| Chromium / Electron (`Chrome_WidgetWin_1`) | 8 | `[-7, 0]` | `[0, 0]` | `[0, 7]` | `[0, 7]` | 3 |
| 其他（Flutter `FLUTTER_RUNNER_WIN32_WINDOW` 等） | 4 | `[-8, 0]` | `[-8, 0]` | `[0, 8]` | `[0, 8]` | 1 |
| 资源管理器 (`CabinetWClass`) | 4 | `[-7, -7]` | `[0, 0]` | `[7, 7]` | `[0, 7]` | 0 |
| 记事本 (`Notepad`) | 1 | `[-5, -5]` | `[0, 0]` | `[5, 5]` | `[5, 5]` | 0 |

补充：部分 Chromium 窗口（如 `Agent`、`WorkBuddy`、`百度网盘`）四边差值全为 `0`；同一进程内也能出现「有阴影」和「无阴影」两种窗口（如 `百度网盘` 是 0，`Clash Party` 是 7）。

| 探针 | 实测数据 | 通过与否 | 结论 |
|---|---|---|---|
| 视觉边界 API 可用性 | 全部窗口 `DwmGetWindowAttribute(9)` 成功 | PASS | 主路径可用，不需要回退 |
| 差值幅度 | 绝对最大 **8 px** | PASS（有上界） | 命中判定公差取 **±8 px** |
| 差值稳定性 | 同风格内稳定（-7/+7 或 -5/+5 或 0） | PASS | **不能用一个全局固定补偿**；按窗口各取各的视觉矩形 |

**结论**：框选命中判定用 `EXTENDED_FRAME_BOUNDS` 作为窗口矩形，选框对窗口做**内缩 8 px** 的宽松求交（或直接对视觉矩形求交，命中阈值 ≥50%）。**不要用 `GetWindowRect`**，否则在最坏情况下每边多算 8 px，小窗口的命中率会被系统性放大。

### 2.3 最小化窗口的坐标

| 探针 | 实测数据 | 通过与否 | 结论 |
|---|---|---|---|
| `IsIconic` 可见窗口数 | 5 | — | 有可用样本 |
| `GetWindowRect` 返回屏幕外哨兵 | **4 / 5** | — | 例：`-32000,-32000,-31840,-31972` |
| `WINDOWPLACEMENT.rcNormalPosition` | 4/5 样本给出真实位置（如 `114,83,1794,1222`，`showCmd=2`） | **PASS** | 快照必须用 `rcNormalPosition` |

**结论**：位置快照 = `WINDOWPLACEMENT`（含 `showCmd`）+ `rcNormalPosition` + 视觉矩形 + 显示器名 + DPI。`GetWindowRect` 只用于非最小化窗口的视觉矩形计算，且取不到时直接判无效。

### 2.4 虚拟桌面 / cloaked

| 探针 | 实测数据 | 通过与否 | 结论 |
|---|---|---|---|
| cloaked `0x2`（shell）窗口数（可见） | 5 | — | 与枚举统计的 11 个（含不可见）不同 |
| `IsWindowOnCurrentVirtualDesktop` 对上述 5 个 | 全部 `true`（不在当前桌面 = **0**） | — | **`DWM_CLOAKED_SHELL` 不等于「在别的虚拟桌面」** |
| `0x1`（app cloaked） | 15 | — | 常见于挂起/UWP 类窗口 |

**结论修正**：原调研文档里「`DWM_CLOAKED_SHELL` 就是其他虚拟桌面窗口」的说法**不成立**，至少在本机这 5 个 shell-cloaked 窗口都在当前桌面。正确做法是：过滤只看「是否 cloaked」，是否在别的桌面必须额外调 `IVirtualDesktopManager.IsWindowOnCurrentVirtualDesktop`，不能靠 cloaked 值推断。

### 2.5 全局热键占用（只读推断，未注册）

从 `%LOCALAPPDATA%\Microsoft\PowerToys` 的配置里解析出的**已占用组合**（节选，均为默认配置）：

| 模块 | 组合 | 配置键 |
|---|---|---|
| **FancyZones** | **`Win+Shift+``** | `fancyzones_editor_hotkey` |
| FancyZones | `Win+PageUp` / `Win+PageDown` | `fancyzones_prevTab/nextTab_hotkey` |
| AltWindowCycle | `Alt+`` / `Alt+Shift+`` | `next/previous_window_shortcut` |
| Shortcut Guide | `Win+Shift+/` | `open_shortcutguide` |
| AdvancedPaste | `Win+Shift+V`、`Win+Ctrl+Alt+V` | `advanced-paste-ui-hotkey` 等 |
| ColorPicker | `Win+Shift+C` | `DefaultActivationShortcut` |
| TextExtractor | `Win+Shift+T` | `DefaultActivationShortcut` |
| Workspaces | `Win+Ctrl+`` | `hotkey` |
| MouseWithoutBorders | `Win+Ctrl+Alt+E/L/R` | `ToggleEasyMouse/LockMachine/Reconnect` |
| AlwaysOnTop | `Alt+Shift+S`、`Win+Ctrl+=/-` | `hotkey` / 透明度热键 |

| 探针 | 实测数据 | 通过与否 | 结论 |
|---|---|---|---|
| 能否只读确定热键被占 | 能读到配置，但**注册状态无法只读确认** | **需实测** | 配置写了 ≠ 当前一定注册成功；反之亦然 |
| 检测冲突的正确方式 | 只能 `RegisterHotKey` 返回 false + `GetLastWin32Error()==1409` | **需实测（探针 P8）** | 静默无效不可检测，必须靠返回值 + 错误码 |

**结论**：Dock 的默认热键候选应避开 `Win+Shift+``（FancyZones）、`Alt+``（AltWindowCycle）、`Win+Shift+C/T/V`、`Win+Ctrl+``。探针 P8 会**故意去注册 `Win+Shift+``** 来验证「失败可被检测」，用完立即注销。

### 2.6 权限 / UIPI 边界（只读部分已确认）

| 探针 | 实测数据 | 通过与否 | 结论 |
|---|---|---|---|
| 自身完整性 | 非提权 | — | Dock 应默认 `asInvoker` |
| UIPI 是否启用 | `EnableLUA=1` | PASS | 低完整性进程向高完整性窗口发消息/拖放会被拦 |
| UAC 提示级别 | `ConsentPromptBehaviorAdmin=5`（对管理员提权在安全桌面确认） | PASS | `AllowSetForegroundWindow` 不会让提权窗口变得可激活 |
| 提权窗口是否存在 | 3 个 | PASS | 交互探针 P1 可以拿它们做只读计数；但**实际激活必须人工构造提权靶窗口** |

**需实测**：非提权进程对提权窗口调 `SetForegroundWindow`、`SetWindowPos`、`RegisterDragDrop` 的真实结果（P1/P6）。只读无法确认，因为这不取决于配置，而取决于完整性级别与窗口所属进程。

## 3. 结论变化（哪些原方案假设被推翻或修正）

| # | 原方案说法 | 实测结果 | 修正 |
|---|---|---|---|
| 1 | 「Chrome/Electron 无边框窗口 `GetWindowRect` 与视觉边界有 7–8 px 阴影差」 | 7 px 和 8 px 都存在，且**同一类里有 3/8 个窗口差值为 0** | 不能写死 7–8 px；按窗口取实际 `EXTENDED_FRAME_BOUNDS`，公差上限取 8 px |
| 2 | 「`DWM_CLOAKED_SHELL`(0x2) 表示被 Shell 隐藏——其他虚拟桌面的窗口属于这类」 | 5 个 0x2 窗口全部 `IsWindowOnCurrentVirtualDesktop=true` | cloaked ≠ 别的桌面；需要额外调 `IVirtualDesktopManager`，或干脆只过滤不判断归属 |
| 3 | 「最小化窗口的 `GetWindowRect` 常是 -32000 哨兵」 | 4/5 实测为 `-32000,-32000,...` | 从「常」升级为「必须假设」：快照一律走 `WINDOWPLACEMENT` |
| 4 | 「枚举 + 过滤即可列出可管理窗口」 | 483 → 17（保留 3.5%） | 过滤链是核心逻辑，必须有单元测试与基线数字 |
| 5 | 「Dock 用 `Win+Shift+`` 之类作为默认热键」 | `Win+Shift+`` 已被 FancyZones 占用，`Alt+`` 被 AltWindowCycle 占用 | 默认热键改为不冲突组合；启动时用 `RegisterHotKey` 返回值做冲突检测，冲突就提示换键 |
| 6 | 「混合 DPI 是主要风险，需一开始就按物理像素建模」 | 本机两屏同为 96 DPI，**无法用实测支持或反驳** | 结论保留为「文档推断」；P3 需在缩放不同的环境跑 |
| 7 | 「UWP 识别靠 `ApplicationFrameWindow` 下钻 `CoreWindow`」 | 当前桌面 0 个 `ApplicationFrameWindow`，**无法验证** | 结论保留为「文档推断」；需先打开一个计算器/设置再跑 P4 |
| 8 | 「提权窗口拖放会失效（UIPI）」 | 只读确认 `EnableLUA=1` 且有 3 个提权窗口，但**未做真实拖放** | 保留为「文档推断 + 条件已具备」，需 P6 补测 |

## 5. 探针工程与运行说明

位置：[`probe/`](../probe/)

```
probe\
  Probe.csproj          主工程（net8.0-windows + WPF，PerMonitorV2 清单，x64）
  app.manifest          asInvoker / PerMonitorV2 / longPathAware
  Native.cs             Win32 P/Invoke 与只读辅助
  Program.cs            入口：默认只打印用法；--readonly / --interactive
  ReadOnly.cs           只读探针（本轮已跑）
  Probes.cs             P1–P8 交互探针
  DragDrop.cs           IDropTarget / CF_HDROP / .lnk 解析
  dpi-child\            无 DPI 感知的控制台子进程，供 P3 对比
  out\                  运行产物（readonly-console.txt / readonly.json / probe-results.json）
  README.md             一页运行说明与每项通过标准
```

运行：

```powershell
cd probe
dotnet build Probe.csproj
.\bin\Debug\net8.0-windows\ProbeHost.exe --readonly     # 随时可跑，不动任何窗口
.\bin\Debug\net8.0-windows\ProbeHost.exe --interactive  # 自建靶窗口，请自己挑时机
```

**没有自动运行任何交互探针**。`--interactive` 会启动 2 个记事本、1 个画图、2 个 WPF 窗口作为靶子，跑完自动关闭；全程不写注册表、不装服务、不注册开机项，热键用完即注销。每项怎么看数据、通过标准见 [`probe/README.md`](../probe/README.md)。

## 6. 基于实测的实施计划

范围按「已确认事实」划 P0，「需要交互结论才能定」划 P1。P0 的验收点全部可以用已实测数字定义。

### P0（可以立刻开工）

| 模块 | 职责 | 依据 | 验收点 |
|---|---|---|---|
| **M1 WindowIndex** | 枚举 + Alt+Tab 过滤 + cloaked 判定 + AppKey | 实测 483→17 | 本机可用窗口落在 **17±2**；`WS_EX_TOOLWINDOW` / 无标题 / cloaked / 零尺寸 一个不漏；`EVENT_OBJECT_*` 增量刷新节流 ≥100 ms |
| **M2 Geometry** | 视觉矩形 + 快照 + 还原 | 实测 ±8 px；最小化 `-32000` | 命中矩形一律取 `EXTENDED_FRAME_BOUNDS`，公差 ±8；最小化窗口快照只读 `rcNormalPosition` |
| **M3 SessionStore** | 组/窗口/布局 JSON 持久化 | R5/R7 | 存 `hwnd + pid + 进程启动时间 + appKey + showCmd + rcNormalPosition + 视觉矩形 + 显示器名 + dpi`；重启后按 appKey 匹配 |
| **M4 DockWindow** | 置顶无激活侧栏 | R1 | `WS_EX_TOPMOST|TOOLWINDOW|NOACTIVATE` + `SW_SHOWNOACTIVATE`；不抢前台；不修改目标窗口样式 |
| **M5 DropIn** | `.lnk` / `.exe` 拖入 | P6 待实测 | 先按 `CF_HDROP` + `.lnk` 解析实现，验收等 P6 数据（若 UIPI 问题成立，默认不提权） |
| **M6 HotkeyMgr** | 注册/注销/冲突提示 | 实测 FancyZones 占 `Win+Shift+`` | 启动注册失败必须读 `GetLastWin32Error()`，1409 时提示换键；默认候选避开 `Win+Shift+``、`Alt+``、`Win+Ctrl+`` |
| **M7 Activator** | 单窗口调取 | P1 待实测 | 先实现「`ShowWindow(SW_RESTORE)` → `SetForegroundWindow` → 失败 `FlashWindowEx`」；把 `AttachThreadInput` / Alt 模拟作为**可关闭的兜底**，等 P1 数据决定是否启用 |

P0 交付判定：在**不改动任何目标窗口样式**的前提下，能做到「拖入 → 点击/热键调取 → 框选成组 → 原位还原」，且 M1/M2/M6 的验收用上表数字。

### P1（等探针数据再定）

| 项 | 依赖的实测结论 | 计划 |
|---|---|---|
| 成组调取 / 一次 `DeferWindowPos` 批量摆位 | P5 误差 ≤1 px | 先全部 `SW_RESTORE`，再统一摆位，最后激活主窗口 |
| 跨 DPI 还原 | P3 | 按 `旧 DPI/新 DPI` 比例缩放再 clamp 到 `rcWork`；本机无法验证，需要在 125%/150% 屏上复测 |
| 套索成组 | P7 命中一致性 | 与矩形共用 z-order 求交，判定改「中心点在多边形内」 |
| UWP 成员 | P4 | 身份用 `PKEY_AppUserModel_ID`，激活走 `ApplicationFrameWindow` |
| 跨虚拟桌面提示 | 已确认 cloaked 不能推断桌面 | 用 `IVirtualDesktopManager.IsWindowOnCurrentVirtualDesktop`，只提示不切换 |
| 重启后恢复 | M3 | 按 appKey 重新匹配；HWND 一律视为失效 |

### 明确不做（本轮实测支持）

- 不做跨进程 `SetParent` 容器化（会破坏目标窗口消息循环/DWM 合成，且本机 3 个提权窗口场景下 UIPI 直接拦）。
- 不做「碰到就算」的框选判定：8 px 阴影差会让任何小选框误选最大化窗口。
- 不把 `DWM_CLOAKED_SHELL` 当作虚拟桌面归属判据。
- 不默认提权运行（`EnableLUA=1` 已确认，提权后拖放会失效）。
- 不修改 `SPI_SETFOREGROUNDLOCKTIMEOUT`（全局副作用，且需重新登录）。
